# 赛事系统当前审查与优化记录

审查对象：`比赛战绩统计应用` v0.7.1  
审查日期：2026-11-14  
范围：存储恢复、多标签页写入、赛事生命周期、晋级与导入导出接口。

## 结论

项目的核心功能和工程基线稳定。当前检查结果：

- TypeScript 检查通过
- ESLint 检查通过
- Vitest：47 个测试文件、394 项测试通过
- 生产构建通过
- 浏览器 smoke 通过：名单导入、开赛、导入赛果、Excel/PNG 导出、刷新恢复和语言切换
- 旧审查中的晋级覆盖、轮空重复、JSON 迁移、快照失败提示、名单分组等问题已经在当前版本处理

本轮重点处理两类仍有实际影响的风险：

1. IndexedDB 主记录无法读取时，旧的 localStorage 镜像可能被静默当成最新存档。
2. 写者锁只在赛事工作区启用，入口和多阶段设置页可能在未取得写权限时修改赛事；无 Web Locks 时的备用锁也缺少原子竞争机制。

## 本轮修复

### 1. 存档恢复需要明确选择

`loadCompetitionResult()` 新增 `recovery` 状态。当 IndexedDB 主记录读取失败或无法验证，而本地仍有可读副本时：

- 不自动载入副本
- 入口页明确提示副本可能过期
- 支持导出原始记录
- 用户确认后才使用可读副本
- 新建或导入前仍会先导出原始记录

这样可以避免浏览器存储异常时把旧进度伪装成最新赛事。

### 2. 写者锁覆盖整个应用

写者锁从工作区提升到应用根组件，入口页、多阶段设置页和赛事工作区统一受保护。未取得锁时：

- 页面默认只读
- 新建、导入、恢复、进入赛事设置等写操作被禁用
- `saveCompetition()` 在存储层再次检查写权限，避免只依赖 UI 状态

### 3. IndexedDB 事务锁

浏览器不支持 Web Locks 时，优先使用 IndexedDB `readwrite` 事务竞争写者租约。读取租约、判断过期、写入新租约在同一个事务中完成，避免两个标签页同时回读后都认为自己获得写权限。IndexedDB 发生异常时才退回 localStorage 租约；只有 IndexedDB 也不可用时才使用 localStorage 兼容路径。最后这一兼容路径不是原子操作，极少数不支持两种原子机制且同时打开多个标签页的旧环境仍有竞争风险。

### 4. 回归测试

新增覆盖：

- IndexedDB 主记录不可读时返回 `recovery`
- `loadCompetition()` 不会静默返回未确认副本
- IndexedDB 写者租约的同时竞争、释放和接管
- 只读标签页调用保存时被拒绝并发出状态通知

## 已确认无需重复修复的内容

- IndexedDB 以事务 `oncomplete` 作为成功信号
- 大存档在 IndexedDB 提交前保留 localStorage 镜像
- 页面隐藏或关闭前会尽力刷新写队列
- 损坏存档与空存档分开处理，并支持导出原始记录
- 晋级重复确认不会覆盖已有下游赛果
- 晋级身份不再按昵称静默去重
- 瑞士轮限制每轮最多一个轮空，并避免同一选手重复轮空
- JSON 备份包含版本信息、大小限制、迁移链和可取消 Worker 解析
- 快照写入有串行队列、归属校验和失败反馈

## 后续建议

1. 增加 Playwright 双标签页测试：模拟一个标签页持锁、另一个标签页尝试修改，验证所有写入口均被阻止。
2. 将存档修订号写入主数据和元信息，用修订号而不是时间戳判断主备新旧。
3. 将存储恢复状态和 `actionError` 统一为全局通知，避免错误只出现在特定页面。
4. 视现场网络要求决定是否把 Google Fonts 改为本地字体资源。
5. 为导出预览、晋级配置和移动端录分页面补充视觉回归场景。
