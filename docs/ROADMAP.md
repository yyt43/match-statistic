# 待办与后续优化

记录 0.7.3 发布时盘点出来、但不在本次范围内的改进项。按「先解决真实赛事痛点」排序，动手前先确认需求还成立。

## 1. 真实赛事回归用例

- 背景：0.7.3 的突围赛签位问题，是靠手工回放 `诗意杯S3-2026-11-21.json` 才发现的，单测覆盖不到完整三赛段链路。
- 目标：把 3–4 场真实赛事的导出 JSON 放进 `src/__fixtures__/`（做脱敏），加一组「导入 → 迁移 → 小组赛确认 → 突围赛确认 → 淘汰赛签表」的快照断言。
- 价值：以后再动落位 / 晋级逻辑，能直接用真实数据兜底。

## 2. 签位引用上游结果

- 背景：现在的 `seating.slots` 只能写「某组某名次 → 某槽」，写不出「A组第 6 名的胜者 → 槽 1」。
- 目标：允许 `slots` 的来源写成「上游赛段某场对局的胜者/败者」，用于双败淘汰、跨赛段交叉等赛制。
- 依赖：需要先在数据模型里给对局加稳定标识，迁移时补齐。

## 3. 双败淘汰赛制（double_elimination）

- 背景：`PairingType` 目前只有瑞士轮和单败淘汰，双败只能靠手工拆成两条链路。
- 目标：内置胜者组/败者组/总决赛结构，签表生成、轮次推导、晋级记录都走同一套 `advancement` 管线。
- 注意：需要先完成第 2 项（签位引用对局结果），否则落位规则表达不出来。

## 4. 循环赛赛制（round_robin）

- 背景：小组人数少（3–5 人）时，瑞士轮不如单循环直观。
- 目标：新增 `round_robin` 赛制，按「每人互打一次」生成全部轮次，排名复用现有 tiebreak 链。

## 5. 选人条件补「每来源上限」

- 背景：`AdvanceSelector.take` 是跨组合并后取前 N，做不出「每组各取最好的 1 个第三名」。
- 目标：加 `takePerGroup`（或把 take 拆成 scope：`overall` / `perGroup`），预览里的「选人条件命中」按新口径展示。

## 6. 模板包注册表

- 背景：诗意杯 S3 的赛段、规则文案、帮助案例都硬编码在 `multiStage.ts` 与 `helpContent.tsx`。
- 目标：把赛事模板抽成可注册的包（`stages` + `ruleText` + `helpCase` + 默认 `playerSchema`），新增赛事只加一个文件。
- 价值：以后接其他赛事不用改核心逻辑，也方便用户自定义模板。

## 7. 其它小项

- 导入时对 `fillPolicy` 做兼容提示：旧数据缺少该字段时给一条「已按直接晋级处理」的提示，而不是静默迁移。
- 导出图片的签表在人数不足时，把空槽标成「待晋级」而不是「轮空」，避免和真正的轮空混淆。
- 多阶段设置页的「落位」摘要补上 fillPolicy，例如「组内名次配对 · 配不成对直接晋级」。
